# Internationalization

The app uses `i18next`, `react-i18next`, browser language detection, chained/localStorage backends, and typed resource files.

Locale resources live under:

- `src/shared/i18n/locales/en/`
- `src/shared/i18n/locales/ru/`

Resource files export `as const` objects. When adding or changing user-facing text, update every supported locale namespace rather than hard-coding strings in components.

Common namespace usage pattern:

```ts
const { t: tCommon } = useTranslation("common");
const { t: tFeatures } = useTranslation("features");

tFeatures(($) => $.newsletter.emailLabel);
```

Routes use typed translation key callbacks in route handles, for example `titleKey`, `descriptionKey`, and `navLabelKey`.

Run `npm run i18next-cli-extract` after changes that should update extracted i18n resources. That command also runs ESLint autofix on `src/shared/i18n/locales`.
